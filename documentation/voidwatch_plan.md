# Voidwatch Implementation Assessment and Completion Plan

## Source baseline

This assessment is based on the following retail reference pages:

- BG Wiki Voidwatch Guide: <https://www.bg-wiki.com/ffxi/Voidwatch_Guide>
- BG Wiki Voidwatch category: <https://www.bg-wiki.com/ffxi/Category:Voidwatch>
- BG Wiki Voidwatch Quests category: <https://www.bg-wiki.com/ffxi/Category:Voidwatch_Quests>
- BG Wiki Provenance page: <https://www.bg-wiki.com/ffxi/Provenance>

The key retail requirements from those sources are:

1. Entry requirements: level 75+, Adventurer's Certificate, and at least one stratum abyssite.
2. Starting-city officers grant the initial crimson, indigo, and jade stratum abyssites; other paths grant white, ashen, hyacinth, and amber abyssites through the Voidwatch questline or regional starters.
3. Voidstones are generated by Voidwatch Officers on a 20-hour base timer, reduced by periapts, and may also be obtained by trading Voiddust.
4. Planar Rifts initiate battles, optionally accept ascent items and phase-displacer clusters, validate the initiator's abyssite tier, and spawn the correct Voidwatch NM.
5. Each participating player may spend a voidstone for individual post-battle rewards from a Riftworn Pyxis; without a stone, participation still allows base rewards and progression credit where appropriate.
6. Spectral alignment has red, blue, green, yellow, and white components. Staggers, synchronic blitz, ascent items, Treasure Hunter, periapts, and Voidwatch campaigns influence final values.
7. Periapts and atmacites provide temporary items, voidstone capacity/timer bonuses, alignment bonuses, and in-battle player augment effects.
8. Stratum abyssites upgrade tier-by-tier after all required NMs in the current tier are defeated and the player asks an Atmacite Refiner for examination.
9. Atmacite Refiners provide atmacite upgrade/equip services and Voidwatch teleportation to battle areas the player can initiate, for cruor.
10. Provenance requires late Jeuno-line Voidwatch progress, uses Kupofried's corundum and petrifacts instead of ordinary voidstones for final access, contains the three Radiance fights and Provenance Watcher, and is entered through Walk of Echoes.
11. Voidwatch has a 30-quest storyline/category footprint, including the city path, Jeuno path, Zilart, Tavnazia, Aht Urhgan, Provenance, and finale quests.

## Current codebase inventory

The repository contains a significant amount of static data for Voidwatch:

- `settings/default/main.lua` already exposes `ENABLE_VOIDWATCH` in the main settings table.
- `sql/npc_list.sql` contains content-tagged Voidwatch NPCs and objects, including 202 Planar Rifts, 201 Riftworn Pyxides, 19 Voidwatch Purveyors, 17 Atmacite Refiners, and 12 Voidwatch Officers.
- `sql/char_points.sql` stores `voidstones` and `kupofried_corundums` point/currency fields that can back the officer and Provenance systems.
- `sql/status_effects.sql` defines the hidden `voidwatcher` effect.
- `sql/mob_pools.sql`, `sql/mob_groups.sql`, and `sql/mob_spawn_points.sql` already include many named Voidwatch NMs, including the starter-nation NMs, Jeuno/Zilart/Tavnazia/Aht Urhgan targets, Radiance encounters, and Provenance Watcher.
- `sql/zone_settings.sql` defines the Provenance zone.
- `src/map/utils/charutils.cpp` includes `VOIDWATCH` in the content-tag filtering list used when content restriction is enabled.

However, the implementation is mostly static data. The repository currently lacks Lua scripts or C++ systems that make the listed NPCs, rifts, pyxides, quests, rewards, alignment, and progression function as retail Voidwatch.

## Accuracy and completeness gaps

### Toggle and content gating

- The main toggle exists as `ENABLE_VOIDWATCH`, but the comment says the system is not implemented.
- Voidwatch SQL rows use the `VOIDWATCH` content tag, so the existing `RESTRICT_CONTENT` mechanism can hide most static Voidwatch NPC/object data when `ENABLE_VOIDWATCH = 0`.
- Missing: a documented operator-facing procedure that explains that both `ENABLE_VOIDWATCH` and `RESTRICT_CONTENT` are required when administrators want the content-tagged data hidden.
- Missing: runtime guards in any future Lua entry points so scripts exit early when `ENABLE_VOIDWATCH = 0` even if the static NPC rows are loaded.

### NPCs and object interaction

- Missing: shared `scripts/globals/voidwatch.lua` module for requirement checks, tier data, rift-to-NM mapping, pyxis state, alignment, rewards, temporary items, and progression.
- Missing: common NPC scripts or zone-local scripts for `Voidwatch_Officer`, `Atmacite_Refiner`, `Voidwatch_Purveyor`, `Planar_Rift`, `Riftworn_Pyxis`, Provenance `Regal_Pawprints`, and Provenance/Walk of Echoes access objects.
- Missing: officer behavior for first abyssites, voidstone timer accrual, Voiddust trades, and voidstone withdrawal/storage.
- Missing: refiner behavior for abyssite upgrade checks, atmacite equip/upgrade, and teleport menus.
- Missing: purveyor shops for phase displacers/ascent items and other retail services.

### Progression and quests

- Missing: all 30 Voidwatch quest scripts listed by BG Wiki's Voidwatch Quests category.
- Missing: quest-region placement and NPC event handling for starter-city, Jeuno, Zilart, Tavnazia, Aht Urhgan, Provenance, and finale quests.
- Missing: char variables and key-item award logic for per-route tier completion, Voidwatcher's emblems, petrifacts, Kupofried's corundums, and final storyline flags.
- Missing: requirement links such as completing the three starter paths before Jeuno initiation and late Jeuno progress before Provenance access.

### Battles

- Missing: Planar Rift initiation flow, including party/alliance validation, level/rank/key-item checks, current-tier checks for initiator, and participation eligibility for non-initiators.
- Missing: support for ascent item trades, phase displacer clusters, voidstone/corundum spending, and battlefield reservation where applicable.
- Missing: battle status state that associates a spawned NM with the initiating rift and eligible players.
- Missing: retail-style Voidwatch weaknesses, proc messages, stagger duration, temporary item restoration, and synchronic blitz.
- Missing: spectral alignment calculations and caps.
- Missing: per-player Riftworn Pyxis reward generation, including individual loot pools, alignment-influenced quality/quantity, key-item/atmacite/periapt acquisition, cruor/EXP awards, campaign overrides, and pyxis cleanup.
- Missing: many NM-specific mechanics, scripts, mods, and drop tables are likely incomplete even where spawn data exists.

### Provenance

- Missing: Walk of Echoes to Provenance access flow and return handling.
- Missing: Kupofried's corundum consumption for the three Radiance fights.
- Missing: Beguiling, Maddening, and Seductive petrifact reward flow.
- Missing: Provenance Watcher entry requiring the three petrifacts.
- Missing: Regal Pawprints atmacite/refiner behavior inside Provenance.
- Missing: Provenance-specific battlefield timers, member limits, titles, and final quest completion.

## Completion plan

### Phase 1: Toggle, data model, and shared module foundation

1. Keep `settings/default/main.lua` as the authoritative toggle location and update the comment to clarify that `ENABLE_VOIDWATCH` gates scripts while `RESTRICT_CONTENT` hides tagged SQL content.
2. Add `scripts/globals/voidwatch.lua` with:
   - `isEnabled()` guard using `xi.settings.main.ENABLE_VOIDWATCH`.
   - constants for stratum colors, tiers, route names, abyssite key items, periapts, atmacites, cells, Voiddust, phase displacers, petrifacts, and corundums.
   - route/tier/NM tables based on BG Wiki's Voidwatch Ops tables.
   - helpers for requirement checks, current abyssite tier, completed NM flags, and upgrade eligibility.
3. Add tests/specs for route table integrity and toggle behavior where practical.

### Phase 2: Officers, voidstones, and starter access

1. Implement shared `Voidwatch_Officer` scripts in all officer zones.
2. Enforce level 75+, Adventurer's Certificate, and enabled-content checks before issuing starter abyssites.
3. Implement voidstone accrual using a persistent timestamp and capacity derived from frontiers periapts.
4. Implement Voiddust trades for voidstone stock.
5. Add clear disabled-content messaging when the toggle is off.

### Phase 3: Atmacite Refiners, purveyors, and teleportation

1. Implement Atmacite Refiner menus for:
   - abyssite examination/upgrades,
   - atmacite equip slots unlocked by emergence periapts,
   - atmacite cruor upgrades,
   - Voidwatch teleportation for accessible zones.
2. Implement Voidwatch Purveyor shops and services, including phase displacers and ascent items.
3. Add teleport cost handling and destination validation by time period and stratum tier.

### Phase 4: Planar Rifts, battle lifecycle, and pyxides

1. Implement Planar Rift scripts for all tagged rifts using rift IDs mapped to zone, route, tier, NM, and pyxis IDs.
2. Validate initiator progression and participating-player reward eligibility.
3. Accept phase displacers and ascent items before spawning.
4. Spawn the correct NM and attach battle state to the rift, NM, and eligible players.
5. Implement Riftworn Pyxis scripts for per-player reward retrieval and cleanup.
6. Add tests around initiation requirements, voidstone spending, and pyxis eligibility.

### Phase 5: Alignment, staggers, temporary items, and rewards

1. Implement spectral alignment state with retail color meanings and caps.
2. Implement weakness/proc candidate generation, stagger detection, messages, and synchronic blitz.
3. Implement temporary item grants/restoration from adaptability/readiness periapts.
4. Implement reward pools with red/blue quality/quantity scaling, green/yellow cruor/EXP scaling, white key-item chances, and Treasure Hunter/ascent item modifiers.
5. Add campaign setting hooks for Voidwatch campaigns that max alignments where desired by server operators.

### Phase 6: Quests and route progression

1. Add all 30 Voidwatch quest scripts in the appropriate quest regions.
2. Connect quest progression to route unlocks, NPC events, emblems, gil rewards, key items, and titles.
3. Gate Jeuno initiation behind completed starter-city paths and `Guardian of the Void` / `Drafted by the Duchy` progression.
4. Gate Provenance access behind late Jeuno-line progress.
5. Add migration-safe char variables for quest and per-NM credit flags.

### Phase 7: Provenance finale

1. Implement Walk of Echoes access objects and Provenance entry/exit flow.
2. Implement the three Radiance encounters with Kupofried's corundum entry costs, 30-minute timers, and 18-member limits.
3. Award Beguiling, Maddening, and Seductive petrifacts.
4. Implement Provenance Watcher access requiring all three petrifacts.
5. Complete finale quests through `Ad Infinitum`, including rewards, titles, and final state cleanup.

1. Audit every Voidwatch NM pool/group/spawn against the BG Wiki route tables and retail battlefield behavior.
2. Implement missing mob scripts, immunities, skill lists, spell lists, families, draw-in, aura mechanics, and special win/loss conditions.

4. Run end-to-end GM test scripts for every route and all Provenance fights.

## Operator toggle method

Voidwatch should be toggled from `settings/default/main.lua` or an overriding settings file:

```lua
-- Hide content-tagged SQL rows when disabled.
RESTRICT_CONTENT = 1,

-- Enable or disable Voidwatch scripts and tagged content.
ENABLE_VOIDWATCH = 1, -- set to 0 to disable
```

Recommended behavior after the scripted system is implemented:

- `ENABLE_VOIDWATCH = 1`: Voidwatch scripts, NPC interactions, rifts, rewards, quests, and Provenance access are enabled.
- `ENABLE_VOIDWATCH = 0`: Voidwatch scripts return disabled-content messages and do not award key items, spend stones, spawn NMs, teleport players, or progress quests.
- `RESTRICT_CONTENT = 1` plus `ENABLE_VOIDWATCH = 0`: content-tagged `VOIDWATCH` NPC/object rows are not loaded, hiding Planar Rifts, Riftworn Pyxides, officers, refiners, purveyors, and related static content.
- `RESTRICT_CONTENT = 0` plus `ENABLE_VOIDWATCH = 0`: static NPC/object rows may still appear, so all scripts must still check `ENABLE_VOIDWATCH` at runtime.

## Feasibility of completing Voidwatch in one PR

Completing retail-accurate Voidwatch is not feasible as a single small PR because the codebase currently lacks the core Lua/C++ systems for a multi-route battle system, all 30 quest scripts, progression storage, per-player reward pyxides, spectral alignment, atmacite/periapt effects, and Provenance finale access. The safe next PR should establish the shared module, runtime toggle guards, and officer/refiner/rift skeletons before filling in battle and quest content route by route.
